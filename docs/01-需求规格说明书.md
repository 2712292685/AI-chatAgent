## 1. 项目定位

一个**运行在终端里的、有固定人设的聊天智能体**。

它不是一个"通用 AI 助手"，也不是一个"可以通过配置变成任意角色的平台"。它更像一个小软件作品：作者决定了这个智能体是谁、怎么说话、有什么脾气，打包出来后，用户打开终端敲一个命令，就开始和一个**具体的人**聊天。

一句话概括：

> 一个装了人设的终端聊天程序，用户只能聊，不能改它的人设。

---

## 2. 目标与非目标

### 2.1 目标（本阶段必须做到）

1. 用户在终端里能进行**连续的多轮对话**，智能体记得本次会话里说过的话。
2. 智能体的**身份（人设）由开发者预先定义**，并在每一轮对话中稳定生效。
3. 回复**逐字流式输出**，等待感尽可能低。
4. 断网、限流、密钥错误等异常**不会让程序崩溃退出**，用户能继续聊。
5. 工程上可安装、可测试、可维护：`uv tool install` 之后全局可用。

### 2.2 非目标（本阶段明确不做）

以下内容**在 MVP 阶段一律不实现**。AI Agent 在开发时若发现自己在做这些事，应立即停止并回到任务范围。

| 非目标 | 说明 |
| --- | --- |
| 对话持久化 | 不存盘、不恢复、不导出。关掉即清空 |
| 命令系统 | 不实现 `/help`、`/clear`、`/persona` 等任何斜杠命令 |
| 多角色 / 角色切换 | 一个程序一个固定人设 |
| 终端 Markdown 渲染 | 不加粗、不高亮代码块，纯文本输出 |
| 图形界面 / Web / 桌面 App | 只做 CLI |
| 联网搜索、工具调用、RAG、知识库 | 不做 |
| 多用户、账号体系、鉴权 | 单人本地使用 |
| 思考过程展示 | 思考模式直接关闭，不展示思维链 |
| 插件机制、主题系统 | 不做 |
| 后续版本的功能预埋 | 不为未确认的未来功能预留接口或占位代码 |

## 3. 用户与使用场景

### 3.1 用户画像

| 角色 | 说明 |
| --- | --- |
| **开发者**（你） | 定义人设、维护代码、发布版本。唯一能修改人设的人 |
| **终端用户** | 拿到程序后直接使用的人。只能聊天，不能修改任何配置 |

### 3.2 典型场景

**场景 A：日常倾诉**

> 下班回家，打开终端敲 `chatagent`，屏幕上出现"小夏 · 你的私人学习搭子"。随口说一句"今天有点学不进去"，它没有立刻给学习建议，而是先问了一句"是卡在哪一章，还是纯粹不想动？"。聊了十来分钟，关掉终端，对话消失。

**场景 B：连续追问**

> 问一个技术问题，它答得不清楚，直接追问"刚才说的第二点再展开"。它知道"第二点"指的是什么，因为上下文还在。

**场景 C：粘贴大段内容**

> 复制一段报错信息（多行）粘进去，每行末尾敲 `\` 续行，最后回车发送。它一次性看到完整报错，而不是被拆成七八条消息。

**场景 D：网络抖动**

> 正聊到第 20 轮，网络断了。屏幕上出现"网络连接失败，已重试 2 次"，然后回到 `你 ›`。用户重新发送同一句话，对话从第 20 轮继续，前面 19 轮一个字都没丢。

## 4. 功能需求

编号规则：`FR-xx`。每条需求都附带可验证的验收标准，测试时逐条对照。

### FR-01 启动与身份加载

程序启动时，按以下顺序完成初始化：

1. 读取 `persona.toml`，解析人设字段。
2. 读取 `config.toml`，解析模型与运行参数。
3. 读取环境变量 `DEEPSEEK_API_KEY`。
4. 把结构化人设渲染成一段 system prompt。
5. 打印启动横幅，进入对话循环。

**验收标准**

- [ ] 三份输入（人设、配置、密钥）任一缺失或格式错误，程序**不进入对话**，而是打印一条指明"哪个文件/哪个变量、缺了什么"的中文提示后退出，退出码非 0。
- [ ] 密钥缺失时的提示必须包含具体设置方法（PowerShell 与 bash 两种写法）。
- [ ] 启动横幅显示人设的 `name` 与 `role`，与 `persona.toml` 中的值一致。
- [ ] 人设字段有任何一个为空字符串时，程序报错并指出字段名，而不是静默拼出半截 prompt。

### FR-02 对话主循环

读取用户输入 → 调用模型 → 输出回复 → 回到等待输入。

**验收标准**

- [ ] 提示符固定为 `你 › `（含尾随空格）。
- [ ] 空输入（直接回车）不发送请求，重新显示提示符。
- [ ] 纯空白输入（空格、制表符）与空输入同等处理。
- [ ] 每次请求前把本次 `user` 消息追加进历史，请求成功后再追加 `assistant` 消息。
- [ ] 请求失败时**不**把残缺的 assistant 消息写入历史。

### FR-03 流式输出

使用 `stream=True` 逐块接收并立即打印。

**验收标准**

- [ ] 首个字符到达即打印，不等全部生成完毕。
- [ ] 回复结束后自动换行，光标停在下一行行首。
- [ ] 流式过程中按键不会被吞掉（除 Ctrl+C 外不做额外输入处理）。
- [ ] 回复正文中不混入任何 UI 前缀重复（`小夏 › ` 只在开头打印一次）。

### FR-04 多轮上下文

每一轮请求都必须携带本次会话的历史消息。

**验收标准**

- [ ] 第 N 轮请求的 `messages` 包含：1 条 system + 之前所有保留的 user/assistant 交替消息 + 本轮 user。
- [ ] 消息顺序严格为 `system, user, assistant, user, assistant, ...`。
- [ ] 第一轮请求的 `messages` 只有 2 条（system + user）。
- [ ] 上下文只在内存中维护，进程退出即丢失，任何情况下都不写磁盘。

### FR-05 上下文窗口裁剪

历史长度超过预算时，从**最早**的消息开始成对丢弃，保证不超出模型限制、不失控成本。

**验收标准**

- [ ] 预算值来自 `config.toml` 的 `context.budget_tokens`，默认 `32000`。
- [ ] 裁剪以"轮"为单位（一条 user + 一条 assistant 一起丢），不允许出现孤立的 assistant 消息打头。
- [ ] 裁剪后最后一条消息必定是本轮 user 消息。
- [ ] 若本轮用户消息本身已超预算，仍照常发送（不吞用户输入），并在 stderr 打印一条警告。
- [ ] 裁剪是可预期的纯函数，输入相同则输出相同，不依赖网络与时钟（便于单测）。

### FR-06 多行输入（反斜杠续行）

**验收标准**

- [ ] 输入行**以 `\` 结尾**时，不发送，改为继续读下一行，多行之间用 `\n` 拼接。
- [ ] 续行状态下提示符改为 `   ... `（前导空格对齐），以表明"还在输入"。
- [ ] 最终发送前，去掉行尾用于续行的 `\`。
- [ ] 连续多行均可续行，无上限（实际上限由 FR-05 处理）。
- [ ] 想表达字面意义的行尾反斜杠，输入 `\\` 结尾，发送时还原为一个 `\`。

### FR-07 退出

**验收标准**

- [ ] 输入 `exit` 或 `quit`（不区分大小写，允许首尾空白）退出。
- [ ] 按 `Ctrl+D`（EOF）退出。
- [ ] 退出时打印一行告别语（内容由人设的 `name` 组合，不硬编码具体人名）。
- [ ] 退出码为 0。
- [ ] `exit`/`quit` 仅作为整行精确匹配生效；"exit 是什么"这类包含该词的内容照常发送给模型。

### FR-08 生成中中断

**验收标准**

- [ ] 流式输出过程中按 `Ctrl+C`：立即停止接收，打印 `[已中断]` 标记，**不退出程序**，回到提示符。
- [ ] 中断的那条回答**不写入**对话历史（用户看不到它，但模型下一轮也不该"记得"它）。
- [ ] 中断后用户可继续正常对话，上下文完好。
- [ ] 空闲等待输入时按 `Ctrl+C`：打印告别语并退出，退出码 0。

### FR-09 错误处理与重试

**验收标准**

- [ ] 错误信息为**中文人话**，不把 Python 堆栈或原始 JSON 抛给用户。
- [ ] 网络类错误（连接失败、超时）与服务端 5xx、限流 429，**自动重试 2 次**（次数由 `config.toml` 的 `api.max_retries` 决定），间隔递增（约 1s、2s），重试期间在 stderr 提示"正在重试 (1/2)"。
- [ ] 密钥无效（401）、余额不足（402）、请求参数错误（400）**不重试**，直接给出对应提示。
- [ ] 所有错误处理完毕后**回到提示符**，程序不退出。
- [ ] 错误提示以 `✗ ` 开头，输出到 stderr。

## 5. 非功能需求

### NFR-01 性能

- 启动到显示横幅：< 500ms（不含网络）。
- 首字延迟：在关闭思考模式的前提下，代表例真机测量 < 2s。
- 内存占用：长时间运行（500 轮以上）稳定在 100MB 以内。

### NFR-02 平台与编码

- 目标平台：**Windows 10/11 优先**，同时兼容 macOS 与 Linux。
- Python 版本：**3.12+**。
- 中文输出不得乱码：启动时显式把 stdout/stderr 编码设为 UTF-8，并处理 Windows 控制台的 ANSI 转义支持。
- 非 TTY 环境（被重定向到文件/管道）时**自动关闭颜色**，避免输出中混入转义码。

### NFR-03 可维护性

- 单文件不超过 250 行；超过则拆分。
- 所有公共函数带类型标注；`mypy` 严格模式通过。
- `ruff check` 与 `ruff format --check` 无告警。
- 核心纯逻辑（人设渲染、上下文裁剪、token 估算、输入行解析）必须有单元测试覆盖。

### NFR-04 安全

- API Key **只从环境变量读取**，任何日志、异常信息、输出中都不得出现密钥内容（包括前几位）。
- 仓库中不得出现真实密钥；`.env` 类文件必须被 `.gitignore` 排除。

### NFR-05 成本可控

- 默认 `temperature = 0.8`（闲聊友好），`max_tokens = 4096`。
- 单轮请求在历史已满预算时，输入 token 不得超过 `budget_tokens + 单条用户消息`。

## 6. 配置规格

### 6.1 环境变量

| 变量 | 必填 | 说明 |
| --- | --- | --- |
| `DEEPSEEK_API_KEY` | 是 | DeepSeek 开放平台申请的密钥，形如 `sk-...` |

> 密钥**永不写入任何文件**，也不进入版本库。

### 6.2 `config.toml`（运行参数，提交进仓库）

```toml
[api]
base_url = "https://api.deepseek.com"
model = "deepseek-flash"
timeout_seconds = 60
max_retries = 2

[model]
thinking = false        # 关闭思考模式（MVP 固定为 false）
temperature = 0.8       # 仅在 thinking = false 时生效
max_tokens = 4096

[context]
budget_tokens = 32000   # 发送给模型的历史预算，不含 system prompt
```

**校验规则**

- `thinking = true` 时程序启动即报错提示"MVP 仅支持关闭思考模式"（因为开启后 temperature 失效，与人设调校目标冲突）。
- `temperature` 取值域 `[0.0, 2.0]`，越界报错。
- `budget_tokens` 必须 ≥ 2000。

### 6.3 `persona.toml`（人设，提交进仓库，由开发者维护）

```toml
name = "小夏"
role = "你的私人学习搭子"
personality = "温和，但不绕弯子。看到问题会直接指出来，不会为了让你舒服而说空话。"
style = "短句为主，偶尔用比喻。不说「作为一个AI」，不用敬语堆砌，不列大段要点除非真的需要。"
background = "和你认识三年，知道你在准备考研，知道你不喜欢被催促，也知道你深夜容易过度焦虑。"
rules = [
    "不主动打探隐私，除非对方先提起",
    "回答超过 300 字要分点，否则读者会走神",
    "不确定的事直接说不确定，绝不编造具体的人名、数据、日期",
]

# 可选：无法归入上面字段的补充设定，原样拼接到 system prompt 末尾
extra = """
你偶尔会提起之前聊过的事，让对话有连续性，但不要生硬地"回忆"。
"""

# 可选：退出时的告别语，缺省为「拜拜，早点休息。」
# farewell = "去睡吧，明天再战。"
```

**字段约束**

| 字段 | 必填 | 类型 | 约束 |
| --- | --- | --- | --- |
| `name` | 是 | string | 1–12 字符，用于提示符与横幅 |
| `role` | 是 | string | 1–40 字符 |
| `personality` | 是 | string | 1–200 字符 |
| `style` | 是 | string | 1–300 字符 |
| `background` | 否 | string | 0–500 字符，缺省视为无 |
| `rules` | 否 | array[string] | 0–20 条，每条 1–120 字符 |
| `extra` | 否 | string | 0–1000 字符 |
| `farewell` | 否 | string | 0–40 字符，退出时的告别语；缺省为「拜拜，早点休息。」 |

> 具体人设文案由开发者在开发期填写。本文档中的"小夏"仅为结构示例，不是最终人设。

## 7. 界面规格

### 7.1 启动横幅

```text
  ╭──────────────────────────────────────────────╮
  │  小夏                                        │
  │  你的私人学习搭子                            │
  ╰──────────────────────────────────────────────╯

  输入内容开始对话。Ctrl+D 或输入 exit 退出。
```

- 边框与人设名使用 ANSI 颜色（人设名高亮，边框暗色）。
- 横幅内的人设名与角色用中文全角对齐考虑，宽度按**显示宽度**计算（中文算 2 列）。
- 非 TTY 时输出无边框纯文本版本。

### 7.2 对话区

```text
你 › 今天有点学不进去
小夏 › 先别急着坐下。是卡在某道题上，还是纯粹不想动？
```

- `你 ›` 用暗色，`小夏 ›` 用人设名 + 主题色。
- 模型回复的换行原样保留，不做自动折行。

### 7.3 特殊状态

| 状态 | 输出 |
| --- | --- |
| 续行中 | `   ... ` |
| 生成被中断 | `\n[已中断]` |
| 重试中 | `! 请求失败（网络超时），正在重试 (1/2)...` |
| 最终错误 | `✗ <中文说明>` |
| 退出 | `小夏 › 拜拜，早点休息。` |

## 9. 全局验收清单

MVP 交付前逐项勾选，全绿才算完成。

**功能**

- [ ] 无密钥启动 → 打印设置指引并退出，退出码非 0
- [ ] 密钥正确 → 正常进入对话
- [ ] 连续 3 轮对话，第 3 轮模型能正确引用第 1 轮的信息
- [ ] 回复为流式逐字出现
- [ ] 反斜杠续行可输入多行并一次发送
- [ ] `exit` / `quit` / Ctrl+D 均可正常退出
- [ ] 生成中 Ctrl+C 打断后仍可继续对话
- [ ] 拔网线后发送消息 → 提示重试 2 次 → 回到提示符 → 恢复网络后可继续聊
- [ ] 错误的密钥 → 明确提示"密钥无效"，不重试
- [ ] 长会话（超过预算）不报错，自动丢弃最早轮次

**工程**

- [ ] `uv run ruff check` 无告警
- [ ] `uv run ruff format --check` 无差异
- [ ] `uv run mypy src` 无错误
- [ ] `uv run pytest` 全绿
- [ ] `uv tool install .` 后，新终端中任意目录可执行 `chatagent`
- [ ] 仓库中不含任何真实密钥
- [ ] `git log` 提交信息全部符合规范
