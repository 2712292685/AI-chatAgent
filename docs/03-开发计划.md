## 1. 版本总览

版本号遵循 SemVer 三段式。**每一版结束时都必须是一个能运行、能演示、能提交的完整状态**，不存在"中间态的半成品"。

| 版本 | 主题 | 一句话目标 | 完成后能做什么 | 参考工作量 |
| --- | --- | --- | --- | --- |
| **v0.1.0** | 骨架跑通 | 打通"配置 → 请求 → 打印" | 敲一句话，真的调到 `deepseek-flash`，回复打在屏幕上 | 0.5–1 天 |
| **v0.2.0** | 对话成型 | 从"问答工具"变成"对话" | 连续聊天，记得前面说过的话；逐字输出；超长自动截断 | 0.5–1 天 |
| **v0.3.0** | 体验打磨 | 从"能跑"到"好用" | 多行输入、颜色、中断、重试、错误友好提示 | 0.5–1 天 |
| **v0.4.0** | 交付就绪 | 从"我的脚本"到"一个软件" | 全局命令可用、测试全绿、README 齐全 | 0.5 天 |
| **v0.5.0** | 机器人控制 | 用自然语言调用 `agent_control` HTTP API | `chatagent-robot` 流式工具调用、参数硬校验、Ctrl+C 停车、mock e2e | 1 天 |

**小版本号的使用规则**（来自需求方要求）：

- 新增功能 → 升 MINOR：`v0.3.0` → `v0.4.0`
- 修 Bug、改文案、调参数、补测试 → 升 PATCH：`v0.3.0` → `v0.3.1` → `v0.3.2`
- 一个版本内允许有多个 PATCH tag，但**每个 tag 必须对应一次 `git tag` 和一条 CHANGELOG 记录**

## 2. 所有版本通用的开发约定

以下约定与谁来实现无关，人类开发者与 AI Agent 都必须遵守。

### 2.1 开工前

1. 读 `docs/01-需求规格说明书.md` 的"需求决策记录"（§8），确认没有理解偏差。
2. 读 `docs/02-项目说明.md` 的模块职责（§4）与目录结构（§3.2），**按既定结构放文件，不自创目录**。
3. 读 `docs/04-Git版本管理规范.md`，尤其"Agent 操作协议"一节。
4. `git status` 确认工作区干净。不干净就先停下来问人。

### 2.2 干活的纪律

- **一个逻辑改动一个提交**。不要攒到最后一次性提交 800 行。
- **不实现当前版本范围外的东西**。看到"以后可能要"的接口，不要预留。需求方明确要求不写后续规划。
- **不改需求文档**。如果实现时发现需求有矛盾，停下来报告，不要自行"合理化"。
- **纯逻辑与 IO 分离**。能写成纯函数的一律写成纯函数，否则测试不了。
- **不引入新的运行时依赖**，除非当前版本范围明确允许。

### 2.3 每次 Git 操作前的报告格式

需求方要求：Agent 每次执行 Git 操作前，必须告诉人"现在做了什么、当前版本是什么内容"。固定格式：

```text
── Git 操作预告 ──────────────────────────────
操作：git commit
内容：v0.2.0 / 第 3 个提交
变更：src/chatagent/context.py（新增）、tests/test_context.py（新增）
目的：实现上下文预算裁剪，使超长历史可自动丢弃最早轮次
提交信息：feat(context): trim history by token budget
──────────────────────────────────────────────
```

**没有这条预告，不得执行写操作类 Git 命令**（`commit` / `tag` / `push` / `merge` / `reset`）。

### 2.4 每版收尾必做

```powershell
uv run ruff check .
uv run ruff format --check .
uv run mypy src
uv run pytest -q
```

四项全绿，才允许打 tag。

### 2.5 每版必须更新进度文档

`docs/05-开发进度.md` 是项目进度的**唯一事实来源**。任何"做到哪了"的问题只以它为准。

**每个版本的完整周期里，至少更新它 4 次：**

| 时机 | 动作 |
| --- | --- |
| 版本开工 | 状态改「🟨 进行中」，填开始日期，更新"当前活跃版本" |
| 每完成一个任务 | 勾选任务清单中对应项 |
| 跑完验收 | 在「验收结果」表里逐条填写实际结果与证据（要写数字，不要只写"通过"） |
| 打 tag 之前 | 状态改「✅ 已完成」，填完成日期、tag、验收通过数、覆盖率，并在 §9 时间线追加一行 |

**硬性要求**

- 未把该版本标记为「已完成」，**不得打 tag**。
- 进度文档的更新与代码变更在同一次提交或紧邻的下一次提交里完成，提交信息用 `docs(progress): ...`。
- 每次修改该文件，同步更新表头的「最后更新」「更新者」「整体进度」。
- 遇到阻塞时，状态改「⛔ 阻塞」并在该文档 §7 写清卡点，不得只留在对话里。

## 3. v0.1.0 —— 骨架跑通

### 3.1 这一版为什么要先做它

这一版刻意做得很"薄"：不做流式、不做历史、不做多行输入。目的是**把最容易翻车的外部依赖提前验证掉**——密钥格式对不对、`base_url` 对不对、模型名 `deepseek-flash` 是否真的可调、`thinking` 参数怎么传。

这些问题如果留到后面才发现，你会在已经写了一千行代码之后被迫返工。

### 3.2 范围内

- 项目骨架：`pyproject.toml`（uv 管理）、`src/` 布局、`.python-version`、`.gitignore`
- `config.toml` 与 `persona.toml`（含示例人设）
- `config.py`：加载并校验三个来源，返回 frozen dataclass
- `persona.py`：字段校验 + `to_system_prompt()` 纯函数
- `errors.py`：异常类型定义
- `llm.py`：**非流式**单次调用 + 基础错误映射（401 / 网络 / 429 / 5xx）
- `render.py`：启动横幅、提示符、普通打印（**无颜色**）
- `cli.py`：REPL 循环（每轮**不带历史**）、`exit`/`quit` 退出、Ctrl+C/Ctrl+D 退出
- `tests/`：`test_config.py`、`test_persona.py`

### 3.3 范围外（做了就是错）

- 流式输出
- 多轮上下文
- 上下文裁剪
- 反斜杠续行
- 颜色 / ANSI 转义
- 自动重试
- 生成中中断（Ctrl+C 在此版就是退出）
- 任何斜杠命令

### 3.4 验收

- [ ] 不设密钥启动，打印设置指引（PowerShell + bash 两种写法）后退出，退出码 1
- [ ] 密钥错误，打印"密钥无效"，退出码 1
- [ ] 密钥正确，能连续对话 3 次，每次都拿到回复（但第 2、3 次不记得第 1 次）
- [ ] 输入 `exit` 退出，打印告别语
- [ ] Ctrl+D 退出
- [ ] `persona.toml` 里 `name` 为空，启动时报错指名该字段
- [ ] `uv run pytest -q` 全绿（至少覆盖：缺字段报错、system prompt 拼接正确、空字段段落省略）
- [ ] `uv run mypy src` 无错误

## 4. v0.2.0 —— 对话成型

### 4.1 这一版变了什么

v0.1 本质上是个"问答工具"：每次请求都是独立的，说过的下一句就忘了。v0.2 把它变成真正的**对话**——历史被记住，并且能控制历史变长后的成本。

同时补上流式输出。这两件事放在同一版，因为它们共同构成"聊天"这件事的体感：**记得住 + 反应快**。

### 4.2 范围内

- `llm.py`：改为流式 `chat_stream()`，返回生成器
- `session.py`：`ChatSession`，持有 system prompt 与历史，`ask()` 产出流式片段
- `context.py`：`estimate_tokens()` + `build_payload()` 预算裁剪
- `cli.py`：接流式输出；历史维护交给 session
- `render.py`：`stream_chunk()` 与收尾换行
- `tests/`：`test_context.py`（裁剪三条不变量 + token 估算边界）

### 4.3 范围外

- 重试、颜色、续行、中断语义、完整错误分类（留给 v0.3）

### 4.4 验收

- [ ] 回复逐字出现，首个字符 < 2s（关思考模式下实测）
- [ ] 第 3 轮问"我刚才说了什么"，模型能正确复述第 1 轮内容
- [ ] 构造 50 轮对话后不报上下文超限错误
- [ ] 裁剪后首条必定是 user 消息（单测验证）
- [ ] 单条超长用户消息仍能发出，stderr 有警告
- [ ] `uv run pytest -q` 全绿，`mypy` 无错

## 5. v0.3.0 —— 体验打磨

### 5.1 这一版解决的问题

到 v0.2 为止，程序"能用"，但"不像个产品"：

- 想贴一段多行报错，会被拆成好几条消息发出去
- 输出纯黑白，人和 AI 分不清
- 网络一抖就报错，得手动重发
- 生成到一半想插话，一按 Ctrl+C 程序直接没了，20 轮对话全部清零

这一版全部修掉。**这一版之后，产品体验就定型了。**

### 5.2 范围内

- `cli.py`：反斜杠续行、`Ctrl+C` 双重语义（生成中打断 / 空闲退出）
- `render.py`：ANSI 配色、TTY 检测、Windows VT 开启、UTF-8 强制、全角对齐边框
- `llm.py`：分类错误映射补全 + 指数退避重试（2 次）
- `errors.py`：中文文案完善
- `session.py`：中断时丢弃残缺回复（不写历史）
- `tests/`：`test_cli_input.py`（退出词、续行判定、`\\` 还原）

### 5.3 范围外

- 输入历史（↑ 键）、Tab 补全
- 命令系统

### 5.4 验收

- [ ] 输入 `line1\` 回车 → 提示符变 `   ... ` → 输入 `line2` 回车 → 服务器收到一条含换行的消息
- [ ] 行尾输入 `\\` → 发送时还原为一个 `\`，不续行
- [ ] 生成中按 Ctrl+C → 屏幕显示 `[已中断]` → 回到提示符 → 继续对话，上下文完好
- [ ] 空闲时按 Ctrl+C → 告别语 → 退出码 0
- [ ] 断开网络发消息 → 提示"正在重试 (1/2)" → 再提示 (2/2) → 给出最终错误 → 回到提示符，程序不退出
- [ ] 401 错误不重试，直接提示密钥无效
- [ ] 输出重定向到文件时不含 `\x1b`
- [ ] Windows Terminal 与 PowerShell 中文均无乱码
- [ ] 横幅边框在中文人设名下仍对齐

## 7. 版本依赖与风险

### 7.1 依赖关系

```text
v0.1.0 ──► v0.2.0 ──► v0.3.0 ──► v0.4.0 ──► v0.5.0
   │          │          │          │          │
   │          │          │          │          └─ 依赖原会话、流式与 REPL
   │          │          │          └─ 依赖前三版的全部功能
   │          │          └─ 依赖流式输出（中断语义的前提）
   │          └─ 依赖 LLM 客户端（改造为流式）
   └─ 依赖 Python 环境与 DeepSeek 密钥
```

**不可乱序**。看似可以并行的 v0.3 的 UI 部分，实际上依赖 v0.2 的流式生成器——没有流式就谈不上"生成中中断"。

### 7.2 风险登记

| 风险 | 概率 | 影响 | 应对 |
| --- | --- | --- | --- |
| `deepseek-flash` 模型名或参数变更 | 中 | v0.1 直接失败 | 模型名走配置而非硬编码，改 `config.toml` 即可 |
| `thinking` 参数位置理解错误 | 中 | 请求 400 | v0.1 就验证；文档明确要求走 `extra_body` |
| Windows 控制台 ANSI 不支持 | 中 | 显示乱码 | 检测失败即降级为无颜色，不崩溃 |
| 流式 + 裁剪组合出现边界 bug | 低 | 对话上下文错乱 | 裁剪函数为纯函数，单测覆盖三条不变量 |
| 中断后历史被污染 | 中 | 模型"记得"一段没说完的话 | 只有生成器正常结束才写历史；v0.3 强制验证 |
| 实现超出当前版本范围 | 中 | 返工 | 每版都有明确的"范围外"清单；验收时逐条对照 |
| 密钥误提交 | 低 | 泄露与扣费 | 只从环境变量读；`.gitignore` 排除 `.env`；提交前 grep 检查 |

### 7.3 每个版本的"止损点"

如果某个版本反复出问题，不要硬扛，按以下方式回退：

| 版本 | 可回退的选择 |
| --- | --- |
| v0.1 调不通 | 先用 curl 验证密钥与模型名可用，再回头查代码 |
| v0.2 裁剪总出错 | 先把 `budget_tokens` 调到极大（等于不裁剪），确认对话本身正常，再单独 debug 裁剪 |
| v0.3 颜色问题多 | 直接关掉颜色（恒返回 `isatty() == False` 的分支），颜色不是核心价值，可推迟到 patch |
| v0.4 覆盖率上不去 | 覆盖率是目标不是手段，先保证 §9 全局验收全过，覆盖率作为 patch 版逐步补 |

## 9. v0.5.0 —— 机器人控制（追加交付）

### 9.1 目标

在不改变原 `chatagent` 行为的前提下，新增 `chatagent-robot`：复用原有人设、
配置、流式模型调用和 REPL 输入语义，通过 DeepSeek function calling 调用
`agent_control` HTTP API，把真实动作结果回报给用户。

### 9.2 范围内

- `pyproject.toml` 增加 `chatagent-robot` 入口，版本升到 0.5.0。
- `config.toml` / 包内配置新增可选 `[robot]`，旧配置仍可加载。
- 新增 robot_client/context/llm/tools/policy/session/cli 模块。
- 工具：状态、移动、转向、姿态、停止、急停、解除急停；不加速度档位。
- 参数硬校验、单动作限制、急停优先、4 轮工具上限。
- Ctrl+C 停止、`interrupted` 工具结果、解除急停二次确认。
- 单元测试与本地 mock SSE + mock API 端到端测试；不访问真实服务。
- README、CHANGELOG、docs/06 与进度文档同步。

### 9.3 范围外

- 不实现 ROS2、SDK、驱动、HTTP 服务端；这些在独立的 `agent_control` 仓库。
- 不接入摄像头、建图、导航或特技动作。
- 不自动改变姿态，不自动重试已执行的动作。
- 不在实现阶段连接真实机器狗或调用真实 DeepSeek API。

### 9.4 验收

- `ruff check`、`ruff format --check`、`mypy src`、`pytest -q` 全绿。
- mock e2e 完整跑通“用户文本 → 流式 tool_call → 200 ms 轮询 → 最终回复”。
- 原 `chatagent` 全部既有测试继续通过，CLI 签名与行为不变。
- 两份 `config.toml` 逐字节一致，`[robot]` 缺省时默认值正确。
- 真机验收留给用户：在仿真联调通过后设置密钥、启动 `agent_control`，从
  0.1–0.2 米/10–20° 开始并手持实体遥控器。
