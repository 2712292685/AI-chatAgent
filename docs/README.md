## 一页纸速览

```text
形态      终端 CLI，运行 chatagent 进入对话
交互      多轮 REPL，纯内存，关掉即清空
人设      单一固定角色，开发者写 persona.toml，用户改不了
输出      流式纯文本，不做 Markdown 渲染
输入      单行 + 反斜杠续行
模型      deepseek-flash（OpenAI 兼容协议），思考模式关闭
密钥      环境变量 DEEPSEEK_API_KEY
上下文    内存全量保存，发送时按 32K token 预算裁剪
错误      分类中文提示 + 自动重试 2 次 + 不退出会话
工具链    uv + ruff + mypy + pytest，Python 3.12
Git       单 main，英文 Conventional Commits，Agent 每步预告
```

## 文档维护约定

1. 这五份文档是**实现的依据**，不是事后描述。代码与文档冲突时，先判断哪一方错了：
   - 代码偏离了文档的**意图** → 改代码
   - 文档写错了细节 → 改文档，并在提交信息里用 `docs:` 前缀
2. 需求变更必须先在 `01` 的 §8 决策记录表中新增或修改条目，再动代码。
3. 新增版本时，在 `03` 中追加一章（目标 / 范围内 / 范围外 / 验收），在 `05` 中追加对应的进度小节，并在 `01` 的决策记录中登记。配套的开发提示词另存，不写入本仓库。
4. 文档与代码在同一次提交里同步更新，不允许"先提交代码，文档以后补"。
5. **`05-开发进度.md` 在每个版本的生命周期内至少更新 4 次**（开工、每完成一项任务、验收完、打 tag 前）。它不参与"事后补"的宽容条款——它是过程文档，必须实时更新。
