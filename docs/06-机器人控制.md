# 机器人控制（v0.5.0）

> 本文只描述 Windows 侧 `chatagent-robot` 如何调用 `agent_control` HTTP 服务。
> ROS2、SDK、驱动与安全验收属于另一个仓库 `agent_control`，Windows 端不直接接触
> ROS2、串口或机器狗 UDP。

## 1. 使用方式

```powershell
# 仓库内
uv run chatagent-robot

# 安装后
uv tool install --force .
chatagent-robot
```

启动前需要 `DEEPSEEK_API_KEY`（与普通 `chatagent` 相同）。机器人服务默认地址是
`http://127.0.0.1:8100`；启动时会请求一次 `GET /api/health`，失败只打印警告，不
阻止进入对话。这样即使服务暂时没起来，也仍然可以先聊天，稍后重试工具调用。

输入、反斜杠续行、`exit` / `quit` / `Ctrl+D` / 空闲 `Ctrl+C` 的语义与普通
`chatagent` 一致。

## 2. 配置

`config.toml` 新增可选段：

```toml
[robot]
base_url = "http://127.0.0.1:8100"
timeout_seconds = 55
max_tool_rounds = 4
```

| 字段 | 默认 | 校验 |
| --- | --- | --- |
| `base_url` | `http://127.0.0.1:8100` | 必须是 http/https URL |
| `timeout_seconds` | 55 | 5–120，单次任务轮询的总等待上限 |
| `max_tool_rounds` | 4 | 1–8，一条用户消息最多执行几轮工具 |

整段 `[robot]` 可以省略，旧配置照常加载。环境变量优先：

- `AGENT_CONTROL_BASE_URL`：覆盖服务地址；WSL2 localhost 转发不工作时改成 API 启动时
  打印的 WSL IP。
- `AGENT_CONTROL_TOKEN`：服务绑定非回环地址时发送
  `Authorization: Bearer <token>`；token 只从环境变量读取，不写配置、不打印、不提交。

## 3. 架构与数据流

```text
chatagent-robot (Windows)
  robot_cli.py
    → robot_session.py
       → robot_llm.py        DeepSeek 流式文本 + tool_calls
       → robot_tools.py      参数校验 + 工具执行
          → robot_client.py  stdlib urllib HTTP
             → agent_control HTTP API (WSL2)
                → 驱动 → 机器狗
```

一次动作：

1. 模型流式返回一个 `tool_calls`，`robot_llm` 以 `index` 为键拼接分片的
   `id` / `name` / `arguments`。
2. `robot_session` 把 assistant tool_calls 写入历史，挑选至多一个动作工具。
3. `robot_tools` 硬校验参数，POST `/api/move`（或 turn/command），拿到 202 + job。
4. `robot_client` 每 200 ms 轮询 `GET /api/jobs/<request_id>`，直到
   `succeeded` / `failed` / `aborted` / `timed_out`。
5. 工具结果 JSON 写回历史；模型看到实际测量值后给出最终中文回复。

`request_id` 使用 UUID4。提交阶段若遇到网络错误或 5xx，会用同一个 id 重试一次；
服务端必须做幂等，重复请求不能重复运动。轮询阶段不重新提交动作。

## 4. HTTP 契约

默认 API 基址 `http://127.0.0.1:8100`。

| 方法 | 路径 | 请求 | 响应 |
| --- | --- | --- | --- |
| GET | `/api/health` | — | 200；不健康时 503 |
| GET | `/api/status` | — | 200 + 缓存状态 |
| POST | `/api/move` | `{request_id?, direction, distance_m}` | 202 + job |
| POST | `/api/turn` | `{request_id?, direction, angle_deg}` | 202 + job |
| POST | `/api/command` | `{request_id?, command}` | 202 + job |
| POST | `/api/stop` | `{}` | 202 |
| POST | `/api/estop` | `{}` | 202 |
| POST | `/api/estop/clear` | `{}` | 202；未锁存 409 |
| GET | `/api/jobs/<request_id>` | — | 200 + job |

- `direction`（move）：`forward` / `backward` / `left` / `right`。
- `direction`（turn）：`left` / `right`。
- `command`：`stand_up` / `sit_down` / `balance_stand` / `move_mode` / `lock`。
- job 至少含 `request_id`、`state`；实际测量通常放在
  `measured` / `actual` / `result.measured` 中，执行器会合并这些来源。
- 错误响应建议形如 `{"error":{"code":"busy","message":"..."}}`；工具结果会保留错误码。

`POST` 响应既可以是 job 本身，也可以是 `{"job": {...}, "request_id": "..."}`
包装；客户端两种都接受。终态只认
`succeeded`、`failed`、`aborted`、`timed_out`。

## 5. 工具

| 工具 | 参数 | 范围与说明 |
| --- | --- | --- |
| `robot_status` | — | 连接、控制权、姿态、电量、位置、故障、状态是否过期 |
| `robot_move` | `direction`, `distance_m` | 前后 0.05–5 m；左右**平移** 0.05–3 m |
| `robot_turn` | `direction`, `angle_deg` | 原地左/右转 1–180° |
| `robot_posture` | `command` | 站立/趴下/平衡/移动模式/锁定 |
| `robot_stop` | — | 停止当前运动，不锁存 |
| `robot_emergency_stop` | — | 软件急停，锁存 |
| `robot_clear_estop` | — | 解除锁存；会让机器狗重新站立，需 `y/N` 确认 |

工具层拒绝布尔值冒充数字、NaN、Infinity、未知字段、未知方向和越界数值。没有速度
档位工具。

工具结果统一为 JSON 字符串，至少包含：

```json
{
  "ok": false,
  "request_id": "…",
  "state": "timed_out",
  "error": "运动超时",
  "error_code": "timeout",
  "measured": {"forward_m": 0.32},
  "requested": {"direction": "forward", "distance_m": 1.0}
}
```

失败、中止、超时或失联时 `ok` 必须为 `false`，不能把请求成功当成动作成功。

## 6. 会话规则

- 历史为 OpenAI 消息 dict，包含 `tool_calls` 与 `tool` 结果；裁剪按完整轮次进行，
  不会拆散 assistant tool_calls 和它的 tool 结果。
- 一条用户消息最多执行 `max_tool_rounds` 轮工具；达到上限后下一次请求不带
  `tools`，并追加“请根据已有结果直接回答”的系统提示，确保有文本回复。
- 一次 assistant 回复最多执行一个动作工具；`robot_status` 可以重复。若同时出现
  急停和别的动作，先执行急停，其余动作返回 `multiple_action_calls`。
- 工具参数 JSON 非法时，把错误作为工具结果交回模型纠正，不崩溃、不执行动作。
- 模型调用只在尚未产出文本或工具调用时重试；工具一旦开始执行，不自动重放。
- `Ctrl+C` 在工具执行或轮询中触发时，CLI 调用 `/api/stop`，session 已经写入
  `state=interrupted` 的工具结果，保持历史成对，然后回到提示符。
- 退出时尽力调用一次 `/api/stop`。

## 7. 安全边界

- 软件急停依赖控制权、网络和进程存活，**不是**实体急停的替代品。始终保留实体
  遥控器，必要时直接断电。
- 实现阶段只使用本地 mock 机器人 API 和 mock OpenAI SSE，不连接真机，也不消耗真实
  API 额度。
- 首次真机测试由用户在场执行：清空场地、机器狗站稳、手持实体遥控器，从
  0.1–0.2 m 和 10–20° 开始，逐步放大。
- 移动闭环依赖里程计。驱动会以实际测量值返回成功/失败；Windows 端的回复必须引用
  这个测量值，不能按“应该到了”来宣布成功。
- 状态过期、API 不可达、任务超时或用户中断时，回复应直接说明，不自动改姿态，也
  不自动重试动作。

## 9. ROS2 侧必须匹配的假设

- POST 的 `request_id` 幂等；同一 id 重复提交不会重复动作。
- 202 响应返回可轮询的 job；job 的 `state` 字段使用上述四种终态。
- 任务实际测量放在 `measured`、`actual` 或 `result.measured`。
- 服务端在客户端停止轮询后通过 lease 自动停车。
- `/api/stop` 可在任务进行时并发调用，返回后所有运动指令归零。
- 非回环绑定时校验 `Authorization: Bearer <AGENT_CONTROL_TOKEN>`。
- 错误响应含稳定错误码，至少覆盖 `busy`、`estop_latched`、`not_ready`、
  `driver_stale`、`timed_out` 等情况。
